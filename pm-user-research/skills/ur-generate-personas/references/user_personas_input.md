# 输入

从当前任务根目录读取普通 Markdown 共享上下文：

```text
<WORK_DIR>/用户调研/<YYYYMMDD><课题>/shared_context.md
```

画像不是任务临时产物，而是供多个调研任务复用的全局用户库，统一写入：

```text
<WORK_DIR>/用户调研/personas_data/
```

因此，输入仍从当前课题目录读取；输出不得再创建在课题目录的 `personas_data/` 下。

不要读取另一个 Skill 的对话内容、用户确认卡内存或完整 `plan.json`。文件使用以下格式：

```markdown
# 用户研究共享上下文

## 任务信息

- 任务标识：20260815手机照片整理
- 调研主题：手机照片整理

## 目标用户

### 全量候选群体

- 学生群体
- 上班族
- 宝爸宝妈
- 内容创作者

### 已选目标群体

- 上班族
- 宝爸宝妈

### 纳入条件

- 可能需要整理或管理手机照片的智能手机用户

### 排除条件

- 无

## 确认信息

- 排除条件由用户明确确认：否
- 状态：已确认
- 确认人：用户
```

- “调研主题”：产品、服务或行为场景。
- “全量候选群体”：全部候选产品受众，不能只保存用户最终选择的群体。
- “已选目标群体”：用户确认选择的群体；选择全部时等于全量候选群体。
- “纳入条件”：可以为空，不得复制成所有画像的既有经历。
- “排除条件”：仅记录用户在调研初期主动、明确提出的条件；用户未明确提出时写“无”。
- “排除条件由用户明确确认”：只有存在用户主动确认的具体排除条件时写“是”，否则写“否”。
- “状态”和“确认人”：必须分别为“已确认”和“用户”；否则停止生成。
- `sample_size`：运行参数，默认 100，不能小于全量候选群体数量。

若共享上下文没有完整候选群体，停止生成并修正该文件；不能把已选目标群体冒充全量受众。

“当前没有相关经历”“尚未使用过该功能”“不确定是否使用过”不能自动成为排除条件。这些人仍可能是产品或功能的潜在受众，应保留在画像范围内。问卷可以根据回答跳过不适用的体验题，但跳题不等于从产品受众中排除。

若“排除条件”不是“无”，但“排除条件由用户明确确认”不是“是”，输入无效，生成器必须停止并要求核实共享上下文。

文件只允许模板中的标题。若出现“产品决策”“研究目标”“假设”“概念”“问卷”等研究设计章节，拒绝输入，而不是忽略后继续生成。
