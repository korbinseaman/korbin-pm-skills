# HarmonyOS 产品经理视角规则

除非用户明确指定其他目标产品，否则使用 `config/constants.yaml` 中配置的默认目标产品。

## 战略判断

只使用全局配置中的战略判断标签，并为每个判断提供证据依据。

含义：

- **已领先**：目标产品在本课题上形成了有意义、可防守的明显优势。
- **基本持平**：整体达到主流竞品水平，没有显著差距。
- **应补齐**：该能力已成为主流/高价值能力，而目标产品存在明显缺口。
- **可跟进**：能力有价值，但尚未形成明确行业 Baseline，应结合成本和用户价值决策。
- **值得领先布局**：行业普遍尚未做好，但用户价值和战略价值较高，适合形成差异化。
- **不建议跟随**：竞品虽有该能力，但价值低、复杂度高、与产品定位不匹配或缺少足够证据支撑。

## 判断原则

不要把“竞品有”自动推导成“我们也应该做”。至少结合：

- 用户任务价值；
- 行业覆盖率；
- 竞品实现成熟度；
- HarmonyOS 当前产品定位；
- 端云/生态能力；
- 实现成本与复杂度；
- 是否能形成真实竞争优势。

## 输出结构

最终建议可按全局配置中的三个时间层级组织：

- **短期补齐**：解决已成为行业 Baseline 的关键缺口。
- **中期强化**：把已有优势从功能覆盖转化成体验或机制优势。
- **长期差异化**：围绕行业空白、生态协同或独特资源建立竞争壁垒。

## 与研究目的联动

### 功能借鉴

重点回答：
- 哪个竞品方案最成熟？
- 哪些交互/机制可以复用？
- 借鉴时有哪些边界和限制？

### 差异化竞争

重点回答：
- 哪些能力已高度同质化？
- 竞品真正拉开差距的点是什么？
- 哪些行业空白值得 HarmonyOS 优先占位？

### 综合分析

同时兼顾 Baseline 补齐与差异化机会。
