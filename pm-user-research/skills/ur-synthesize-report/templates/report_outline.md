# HTML 报告结构

1. 标题与醒目的数据来源披露。
2. 交互工作台：可选择筛选题目及一个或多个选项（同题选项为“任一满足”，不同题目条件为“同时满足”）；显示当前样本数；逐题展示频数/比例表，每题独立切换表格、饼图、圆环、柱状、条形、折线；交叉分析提供 X 最多 2 题、Y 最多 10 题的选择配置、交换和结果表。下载窗口选择 DOCX、PPTX、XLSX，导出真正 Office 包而非重命名网页；保留 CSV。提供清除条件、下载报告和三页结论 PPT（含百分比图表）。筛选只实时更新封闭题描述统计和页面内交叉表，不自动改写研究结论、主题、研究者预设的交叉/量表分析或建议。
3. 研究决策、研究目标、问卷方法和证据边界。
4. 批次 `run_id`、总样本、完成/失败、清理剔除记录、可分析样本、数据质量和实际模型分布。
5. 单题描述统计：单选/多选的频数与百分比，量表的均值与标准差，排序的首选与平均名次。
6. 高级与交叉分析：分组交叉、量表信效度的结果，或清楚说明不适用的原因。
7. 关键发现：每节按“发现 → 图表/证据 → 解释 → 限制 → 产品含义”。
8. 分群观察与反例。
9. 痛点和需求优先级。
10. 建议：立即修订研究工具、下一步真实研究、产品探索项。
11. 限制与未回答问题。不要在 `<YYYYMMDD><调研课题>_调研报告.html` 显示“证据索引”；证据 ID 只保留在 `analysis_summary.json` 与质量审计中供回溯。

HTML 使用 [report.css](report.css) 的阅读型布局：白底和浅灰分隔，以单一蓝色强调选中状态和图表，采用紧凑的标题/导出栏和样本指标行。普通分析/交叉分析/调研分析结论/问卷质量报告四个 Tab 位于分析区顶部，题目/选项筛选只在普通分析和交叉分析 Tab 下方显示，共用筛选条件；下方逐题展示全宽卡片。窄屏控件纵向排布，表格横向滚动。数据明细、全批次图表、预设分析及清理记录按需展开；结论页保留目标导向的分析叙事，质量报告单独保留方法及限制。交互控件必须无需网络连接；筛选数据仅保留匿名封闭题答案，Office 和交叉表 CSV 下载都由浏览器本地完成。

合成数据必须说明其不能替代真实研究。若读取 `persons_summary.html`，仅将其作为“样本构成说明”单独披露；不得与回答结果共用一张比例图，也不得把它写成回答证据或分群结果。

交互图表下附完整选项及频数/百分比表。多选题饼图/圆环按选择人次归一化并注明，与表格的有效受访者百分比区分；排序题的图表按第一选择，交叉表按是否选择，分别说明口径。交叉表保留空组和零频选项，显示组人数、目标题有效分母与空白数。下方静态图表标为“全批次描述统计”，不得使读者误以为研究结论随筛选自动变化。

页面使用“普通分析”“交叉分析”“调研分析结论”“问卷质量报告”四个独立 Tab，默认普通分析。前两页共用筛选；后两页隐藏筛选区，保持清理后全批次口径。结论页按背景与目的 → 用户现状 → 用户诉求与痛点 → 目标对应的关键结论展开，提供2–3页带数据图表的 PPT。移除下方重复的研究目标、主题/痛点/需求、建议与下一步验证正文区块。分群与研究者分析、全批次描述统计、数据质量与清理记录、限制与未回答问题只放在“问卷质量报告”。Office 导出按当前 Tab 隔离，质量报告不得混入筛选后样本。

当前报告交互要求：结论页提供2–3页 PPT（默认3页），依次呈现背景/目的与用户现状、用户诉求与痛点、目标对应的关键结论，并配相关题目图表、实际分母及来源限制。以证据支持现状与诉求，不补造未提供的背景、原因或研究目标。质量明细放入“问卷质量报告”Tab。普通分析图形按百分比绘制并标注；多选饼图/圆环按选择人次占比，其他图形按有效受访者占比。不提供保存报告及 PNG/SVG 导出。
