# 调研报告幻灯片：结论与后续工作输入

## 输入与底稿

使用已核对的 `research_context`、`goal_coverage`、`descriptive_results`、`themes`、`recommendations`、`limitations`；回答 Excel 是统计与引语的唯一证据。先在 `analysis_summary.json` 增加：

```json
{
  "conclusion_slides": [
    {
      "page_role": "current_state",
      "title": "一句话核心结论，直接回答研究问题",
      "research_question": "本页回答的目标问题",
      "goal_ids": ["G1"],
      "supporting_data": [
        {"question_id": "Q1", "option_label": "与原始统计完全一致的选项", "evidence_angle": "current_behavior", "proves": "说明当前行为"},
        {"question_id": "Q2", "option_label": "另一项原始统计选项", "evidence_angle": "friction", "proves": "说明关键障碍"}
      ],
      "interpretation": "这些数据合起来意味着什么；不声称未经证明的因果关系",
      "product_implication": "对下一步产品工作的启示，非已验证方案",
      "counterevidence_or_limit": "反例、样本与题目口径限制"
    }
  ],
  "next_step_inputs": {
    "competitor_analysis": [
      {
        "input": "需比较的用户任务/场景及为什么要比较",
        "compare_dimensions": "拟比较的功能机制、流程或体验维度",
        "verification_question": "竞品事实尚待核实的具体问题",
        "decision_use": "结果将用于哪项产品决策",
        "question_ids": ["Q3"],
        "evidence_ids": [],
        "status": "research_finding"
      }
    ],
    "experience_design": [
      {
        "input": "有证据支持的目标用户与任务场景",
        "design_implication": "待设计的交互目标/体验原则及边界",
        "validation_question": "原型或后续研究需验证的问题",
        "question_ids": ["Q3"],
        "evidence_ids": [],
        "status": "product_hypothesis"
      }
    ]
  }
}
```

`conclusion_slides` 恰好两项，顺序固定：第 1 页 `page_role=current_state`，第 2 页 `page_role=needs_and_conditions`。第 1 页的 2–3 项 `supporting_data` 必须同时含 `current_behavior` 和 `friction` 两种 `evidence_angle`；第 2 页必须同时含 `need_priority` 和 `decision_condition`。人数、比例和有效分母由底稿读取，不手填、猜测或用全样本替换题目有效分母。每项 `question_id`、`option_label` 与 `proves` 必须能准确回溯和解释；允许同题不同选项，但不能重复同一统计。用户原声可帮助解释，不算支撑数据；小样本、多选非互斥、选择性偏差和相反证据必须披露。

`status` 取 `research_finding`、`product_hypothesis` 或 `to_verify`。每项后续输入至少给出可回溯的 `question_ids` 或 `evidence_ids`；证据不足时不填写为已证实的输入，把缺口写入页内“待补研究”。`evidence_ids` 使用已有的原始回答证据 ID，不放姓名或可识别原话。竞品名单可以是用户指定或下一步拟查对象，不能写成已核实的竞品能力。

## 页数与版式

- 第 1 页“现状与关键问题”：回答目标用户当前在什么场景完成什么任务、采取什么方式，以及最突出的障碍/未满足处。2–3 项数据至少有一项当前行为/使用现状，一项困难/失败/绕行或不满意；第三项可补影响范围或反例。标题是一句经证据支持的现状判断，不写功能建议。页末只给出下一步值得验证的问题。
- 第 2 页“需求优先级与决策条件”：回答哪个需求/任务更值得优先研究，以及用户采纳、选择或付费受什么条件约束。2–3 项数据至少有一项需求或任务优先级，一项采纳/选择/付费门槛；第三项可补偏好差异或反例。没有价格题就写实际有据的采用条件，不推导价格；概念意愿不得写成真实行为。页末说明对竞品维度和原型验证的输入。
- 两页均为“结论标题 → 研究问题 → 2–3 项数据及各自证明的判断 → 综合解释 → 产品含义/反例限制”。按研究目标挑选各页证据，不按题号顺序汇报。题号、选项、人数、百分比、有效分母、单/多选口径必须可核对。若任一页缺少所需的两种证据角度，不用重复数据或无关题目凑页；报告证据缺口并暂缓正式幻灯片。
- 后 2 页（工作输入）：一页为竞品分析 Brief，明确“要比较什么、为什么、核实什么、如何用于决策”；一页为体验定义 Brief，明确“谁在什么场景完成什么任务、要解决什么体验问题、通过什么原型验证”。每页最多 3 条，保留证据题号、发现/假设状态与待验证问题。
- 每页页脚标明数据来源、批次/运行 ID、图表有效分母及主要限制；合成数据注明只适合生成假设。图表使用可编辑形状与文字，避免仅截图。事实、综合判断和待验证产品假设分别标记；不把相关性写成因果，也不把产品建议写成调研事实。

### 图表选择规则（两页逐页判定）

1. **100% 堆叠条**：2–3 项证据恰好来自同一道单选题的全部互斥且穷尽的选项，选项人数合计等于该题有效分母。用于展示整体构成，如采用态度的不同选择；每段标注人数、百分比和共同分母。仅选出部分选项时不能画成 100%。
2. **独立水平百分比条**：来自不同题目、不同有效分母、多选题、或者同一道单选题的部分选项时使用。各条统一 0–100% 刻度，每条标明题号、人数、百分比和自身有效分母；多选注明可重叠，不把各条比例相加。长选项名称优先水平条而非柱状图。
3. **不使用饼图、圆环图和折线图**：多选不构成互斥总体；跨题指标不构成同一个整体；单批次横截面数据不代表时间趋势。仅当底稿另有经过核对的同口径时间序列或可比群组分析，才在独立分析页考虑趋势线或分组图，不把它们塞进这两页的 2–3 点证据图中。

图表只画本页的 2–3 项支撑数据，不借用无关题的完整分布。图表与文字共享同一 `chart.type`、数据和口径，内置生成器自动在 `composition_100` 与 `comparison_bars` 间选择；若读者仅看图无法区分分母或题型，应保留旁注而非省略证据口径。

## 产出与验收

按 `<YYYYMMDD><调研课题>_调研报告幻灯片.pptx` 输出至本次任务目录。合成 CLI 在完成结论底稿后生成独立 PPTX；真实 Excel 模式的适配流程也调用同一个幻灯片构建器，不把真实数据套入合成 CLI。HTML 的“调研分析结论”Tab 与浏览器 PPTX 下载使用同一组页内容。

逐页检查：结论恰好两页、按现状与问题／需求与决策条件排序，一页恰有一个核心结论和 2–3 项不同的直接支撑数据；两种必需证据角度齐全，每项能准确说明 `proves`，并与原始 Excel 和底稿对应。核对 100% 堆叠条的互斥、穷尽和共同分母条件；其余独立水平条分别标注分母，不暗示总和。研究目标被回答或标为缺口；竞品页没有虚构的竞品事实；体验页没有未经验证的解决方案承诺；来源和限制可见；独立 PPTX、HTML 与浏览器下载内容一致且文件能打开。
