# 用户调研问卷设计 Lite

围绕产品决策建立最短但完整的证据链，输出低偏差、可配置、可分析的定量问卷。优先保证题目质量和关键证据，不生成无决策用途的问题或非必要派生文件。

## 输入

必须确定：

- **课题描述**：研究什么产品、功能、任务或用户问题。
- **调研目标**：问卷需要回答什么，或支持什么产品决策。
- **问卷场景**：原始需求洞察、关键假设验证、产品方案选择、满意度调查，四选一。

按需使用：产品决策、目标用户、题量上限、待验证方案或概念材料、目标导出平台。

输入完整且不存在会改变研究方向的歧义时，直接进入问卷设计，不要求用户再次确认。只有以下情况才暂停并一次询问最多 3 项：

- 三个必填项无法可靠推导或彼此矛盾；
- 目标用户范围会改变筛选路径；
- 关键假设验证缺少必要概念内容；
- 产品方案选择缺少至少两个信息对称、可比较的方案。

提问时优先给出 2–3 个具体选项。只展示需要决定的事项，不让用户重新确认已经明确的信息。

## 工作流程

### 1. 锁定研究设计

**输入**：用户请求及材料。

**处理**：

1. 明确研究对象，避免用母产品行为代替具体功能或任务证据。
2. 将目标收敛为 1–3 个问卷可回答的问题，并确定结果将支持的产品决策。
3. 为每个目标只保留会影响决策的证据；删除“顺便了解”的信息。
4. 设计中性的问卷标题和描述，说明主题、预计时长、数据用途及必要隐私提示。

**输出**：课题、问卷场景、研究对象、目标用户、产品决策、研究目标和核心证据的简洁摘要。该摘要直接进入 Step 2，不生成独立中间文件。

### 2. 建立证据链并设计问卷

**输入**：Step 1 的研究摘要。

**处理**：

1. 只读取当前问卷场景对应的一份模板，继承其证据结构，不复制示例业务内容：

| 问卷场景 | 模板 | 推荐证据顺序 |
|---|---|---|
| 原始需求洞察 | [原始需求洞察](templates/questionnaire-original-needs-discovery.md) | 近期行为 → 最近一次任务 → 问题 → 后果与应对 → 优先级 |
| 关键假设验证 | [关键假设验证](templates/questionnaire-key-hypothesis-validation.md) | 概念前行为与问题 → 中性概念 → 增量价值 → 顾虑与采用条件 |
| 产品方案选择 | [产品方案选择](templates/questionnaire-solution-selection.md) | 相关行为 → 方案同构呈现 → 首选 → 选择理由与排斥因素 |
| 满意度调查 | [满意度调查](templates/questionnaire-satisfaction-survey.md) | 近期使用 → 整体满意度 → 维度诊断 → 改进优先级 |

2. 按“人口特征（按需）→ 用户筛选（按需）→ 场景核心证据链 → 开放补充（按需）”组织模块。人口特征只有进入配额或分析时才加入；未指定时通常保留年龄和手机品牌，性别仅在有明确分析用途时加入。
3. 根据用户上限确定题量；未指定时优先控制最长路径在 8–12 题，只有核心证据无法覆盖时才增加。
4. 直接完成标题、描述、题目、选项和必要逻辑。题型由证据决定，不套用固定数量配额。

**核心设计规则**：

- 每道题必须对应研究证据、筛选资格或必要分析分组。
- 原始需求洞察先问真实行为和问题，再出现未来功能或解决方向。
- 行为题使用明确时间窗或最近一次经历；无相关经历者不评价使用体验。
- 题干脱离前题仍能理解，一题只测一个主要变量。
- 单选选项互斥且基本穷尽；多选设置合理上限和排他项。
- 一个选项只表达一个可编码含义；可独立开发或取舍的能力必须拆开。
- 选项使用普通用户能理解的简短表达，不混合场景、功能、结果和原因。
- 需要优先级结论时，使用 Top 1、Top-N 或排序；之后至少追问一次选择原因、期待结果或触发场景。
- 概念和方案使用中性文案；多方案的信息量、结构和语气保持对称。
- 只有实际存在时才写题目关联、跳题逻辑、选项关联或填写提示。

复杂分支、动态选项、矩阵量表或新概念材料需要详细规则时，再读取 [题目设计标准](references/question-design-standards.md)；模块选择仍无法确定时，再读取 [问卷模块设计](references/survey-patterns.md)。

**输出**：完整的 `questionnaire.md` 草稿，以及一份简洁的“研究目标—核心证据—题号”映射。

### 3. 审查并按需交付

**输入**：问卷草稿和目标—证据—题号映射。

**处理**：

1. 检查每个目标都有证据题，删除重复、无法回忆或不能进入分析的问题。
2. 检查诱导、双重问题、选项重叠、缺少时间窗和无资格评价。
3. 无分支问卷检查一条完整路径；存在筛选、显示关联或动态选项时，检查符合条件、无经历和边界答案路径。复杂逻辑再读取 [发布检查清单](references/questionnaire-logic-checklist.md)。
4. 运行 `scripts/lint_questionnaire.py <questionnaire.md>`，修复结构阻断后交付。
5. 仅在用户明确需要时生成派生文件，并只读取对应格式规范：
   - AI 模拟作答：读取 [模拟作答格式](references/simulator-questionnaire-format.md)，生成 `questionnaire_for_simulator.md`。
   - UserClub：读取 [UserClub 格式](references/userclub-import-format.md)，生成 `questionnaire_for_userclub.txt`。
   - 问卷星：读取 [问卷星格式](references/wenjuanxing-import-format.md)，生成 `questionnaire_for_wenjuanxing.txt`。

**输出**：默认交付以下两份文件：

- `questionnaire.md`：问卷的唯一权威来源。
- `survey-design-desc.html`：只包含已确认输入、目标—证据—题号映射、模块与路径摘要、分析建议和必须由用户决定的审查点；默认不重复嵌入整份问卷。

当用户要求单文件评审时，才把完整问卷附在 HTML 文末；当用户指定模拟或导入平台时，再增加对应派生文件。所有文件保存到 `<WORK_DIR>/用户调研/<YYYYMMDD><课题>/`。

## 交付摘要

交付时只报告文件路径、问卷场景、总题数、最长路径、预计时长、题型分布和用户审查点。没有审查点时写“无”。不复述内部工作过程，不自动启动模拟作答、问卷投放或数据分析。
