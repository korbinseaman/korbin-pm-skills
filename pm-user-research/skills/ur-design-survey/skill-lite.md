# 用户调研问卷设计 Lite

保留六步研究流程与正式版的证据质量标准，减少重复确认和非必要派生文件。深度取决于能否解释行为、区分关键判断并支持决策，不以题量衡量。

## 输入

必须确定：课题描述、调研目标、四选一问卷场景（原始需求洞察、关键假设验证、产品方案选择、满意度调查）。
按需使用：产品决策、目标用户、题量上限、待验证方案或概念材料、目标导出平台。

## 工作流程

### 1. 明确研究方向

**输入**：用户请求及材料。

**处理**：
1. 提取必选和已有可选输入，保留已明确的用户意图。
2. 输入完整时直接进入 Step 2，不要求重复确认。仅对无法可靠推导或矛盾的研究方向、会改变筛选的受众、缺失的必要概念或至少两个可比方案，一次集中询问最多 3 项。
3. 提问提供具体候选方向，不编造方案或用户事实。

**输出**：研究输入摘要及既有约束，不生成独立中间文件。

### 2. 建立研究设计与分析设计

**输入**：Step 1 的研究输入摘要。

**处理**：
1. 明确研究对象，将目标收敛为 1–3 个能支持决策的问题。
   明确用户没有要求的问题；若只调研真实付费习惯、需要哪些能力和是否愿为系统图库额外付费，不扩展为事件障碍诊断、功能 Top 1 或现有图库 AI 使用追踪。
2. 读取 [深入调研与分析设计](references/research-depth-design.md)，建立目标、待判断问题、可能解释及反证、分析变量、回答人群与分母、所需证据、比较方法、产品动作和解释边界的紧凑表格。
3. 不用母产品行为代替具体功能证据，不把意愿解释为采用率，不编造成功阈值。
4. 写中性标题和描述，说明主题、预计时长、数据用途及必要隐私提示。

**输出**：研究设计包，保留 Step 1 信息并追加分析设计、标题和描述。

### 3. 确定模块与分群蓝图

**输入**：Step 2 的研究设计包。

**处理**：
1. 只读取当前场景对应的一份模板，继承证据结构，替换示例业务内容：

| 场景 | 模板 | 核心证据 |
|---|---|---|
| 原始需求洞察 | [需求洞察](templates/questionnaire-original-needs-discovery.md) | 按目标选真实行为、能力需求或问题机制；只有决策需要时才进入事件后果与优先问题 |
| 关键假设验证 | [假设验证](templates/questionnaire-key-hypothesis-validation.md) | 概念前证据、任务匹配、增量价值、拒绝与采用条件 |
| 产品方案选择 | [方案选择](templates/questionnaire-solution-selection.md) | 实际任务、同构方案、首选及原因、不适合情境 |
| 满意度调查 | [满意度调查](templates/questionnaire-satisfaction-survey.md) | 近期体验、满意度、结果落差、改进取舍 |

2. 只区分目标真正需要的付款、需求、功能使用或认知状态；无经历者不评价体验，有相关需求的未用者按目标保留。
3. 若目标研究问题机制，围绕同一次关键事件建立任务、结果和应对的证据链。若目标是付费机会或能力需求覆盖，直接测过去实际付费、逐项能力需求、使用次数、图库付费态度及条件；不机械加事件题。
4. 人口特征按配额或分析用途选择；未指定时通常保留年龄和手机品牌，性别需有明确分析用途。保留 Lite 原有策略。
5. 遵守用户上限；无上限时以完整核心证据为准，8–12 题只是起始参考，不能为维持题量删除必要追问。模块选择不清楚时读取 [模块设计](references/survey-patterns.md)，Lite 的人口策略以本文件为准。

**输出**：模块目标、证据、题数、出现条件、回答资格和最长路径的蓝图，连同研究设计包进入 Step 4。

### 4. 分模块设计题目

**输入**：Step 3 的设计包与蓝图。

**处理**：
1. 每题明确研究对象、目标证据、分析变量、回答资格、回忆锚点和决策用途；用紧凑逐题表记录，复杂题再展开。
2. 读取 [题目设计标准](references/question-design-standards.md)，从变量推导同层级、可区分、可理解的选项，不套用通用原因清单。
3. 保持真实行为先于概念，题干独立可理解，一题测一个主要变量；多选限制和排他项明确。
4. 需要第一优先级时用 Top 1 或等效取舍，随后收集具体选择依据。保留没有问题、现有方式足够、无法判断等合理反证。
5. 必要定义和概念材料按实际位置展示；模板使用说明、成功标准、测量卡不进入受访者问卷。

**输出**：完整主问卷草稿、逐题测量映射和目标—证据—题号表。

### 5. 审查问卷

**输入**：Step 4 草稿及设计映射。

**处理**：
1. 按深入调研规范反向验收：答案能否计算指标、区分关键解释、导致不同动作、支持反证；无法识别的部分明确边界。
2. 检查题干与选项质量，按 [发布检查清单](references/questionnaire-logic-checklist.md) 走查实际存在的完整、无经历和边界路径。Lite 默认不附完整 HTML 问卷，其余质量门禁一致。
3. 运行 `scripts/lint_questionnaire.py <questionnaire.md>`；脚本只查结构和措辞风险，不替代语义验收。
4. 集中修复具体问题并复查受影响的映射与路径；必要时回到 Step 2–4，不以多轮无目标重写代替验证。

**输出**：可交付问卷、分析设计及必须由用户决定的审查点（无则写“无”）。

### 6. 生成交付文件

**输入**：Step 5 定稿及设计信息。

**处理**：
1. 默认生成 `questionnaire.md` 和 `survey-design-desc.html`，后者包含研究输入、分析设计、目标—证据—题号映射、模块与路径摘要、分析建议、解释边界和审查点。
2. 用户要求单文件评审时才在 HTML 文末附完整问卷。
3. 用户指定导出平台时读取对应规范并生成版本：
   - [模拟作答](references/simulator-questionnaire-format.md)：`questionnaire_for_simulator.md`。
   - [UserClub](references/userclub-import-format.md)：`questionnaire_for_userclub.txt`。
   - [问卷星](references/wenjuanxing-import-format.md)：`questionnaire_for_wenjuanxing.txt`。
4. 可运行 `scripts/export_questionnaire.py <questionnaire.md> --formats simulator wenjuanxing`，只选择需要的格式。题型不支持时处理具体缺口，不能猜测语法或静默漏题。

**输出**：默认两份文件及明确请求的派生版本，保存到 `<WORK_DIR>/用户调研/<YYYYMMDD><课题>/`。主问卷为唯一权威来源，各版本同步题意、选项、顺序和逻辑。

## 执行与交付

六步不省略，质量优先；按需读规范，已读且未变的不重复读取；设计信息紧凑传递，定稿后集中导出。只对具体缺口返工，不设固定耗时门槛。

交付报告文件路径、问卷场景、总题数、最长路径、预计时长、题型分布和用户审查点，不复述内部过程，不自动启动投放、模拟或数据分析。
