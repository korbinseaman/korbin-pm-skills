# HTML 报告结构

1. 标题与醒目的数据来源披露。
2. 交互筛选与保存：可按一个或多个不同封闭题选项叠加筛选（条件为“同时满足”，同一题只保留一个选项）；显示当前样本数；提供清除条件、保存当前筛选报告、下载 PNG 与 SVG 图片。筛选只实时更新封闭题描述统计，不自动改写研究结论、主题、交叉/量表分析或建议。
3. 研究决策、研究目标、问卷方法和证据边界。
4. 批次 `run_id`、总样本、完成/失败、清理剔除记录、可分析样本、数据质量和实际模型分布。
5. 单题描述统计：单选/多选的频数与百分比，量表的均值与标准差，排序的首选与平均名次。
6. 高级与交叉分析：分组交叉、量表信效度的结果，或清楚说明不适用的原因。
7. 关键发现：每节按“发现 → 图表/证据 → 解释 → 限制 → 产品含义”。
8. 分群观察与反例。
9. 痛点和需求优先级。
10. 建议：立即修订研究工具、下一步真实研究、产品探索项。
11. 限制与未回答问题。不要在 `report.html` 显示“证据索引”；证据 ID 只保留在 `analysis_summary.json` 与质量审计中供回溯。

HTML 使用单栏阅读流、系统字体、高对比度颜色、响应式布局和内嵌 SVG。交互控件必须无需网络连接；筛选数据仅保留匿名封闭题答案，保存 HTML 与 PNG/SVG 下载都由浏览器本地完成。不要把报告做成只有指标卡和图表的仪表盘。

合成数据必须说明其不能替代真实研究。若读取 `persons_summary.html`，仅将其作为“样本构成说明”单独披露；不得与回答结果共用一张比例图，也不得把它写成回答证据或分群结果。
