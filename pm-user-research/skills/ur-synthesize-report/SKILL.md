# 综合问卷数据并输出调研报告

将一批问卷回答转为可回溯到 Excel 原始行、能支持研究决策的报告。真实与合成数据共用下述五步流程，仅在输入适配、来源披露和质量判断上区分；不接收独立访谈记录。

回答 Excel 是回答、统计和引语的唯一证据来源。问卷与数据字典定义题型、编码和逻辑，研究设计说明定义背景与目标；不得将设计假设或画像当作回答发现。

## 输入与模式

先锁定用户指定的文件、工作表、回答粒度和数据来源，不自行选择最新批次、跨文件合并或读取任务级共享上下文。来源必须由用户说明或明确的生成记录确认，不能仅凭文件名或缺少模型列判为真实；不明确时询问，真实与合成混合时先分开并确认分析范围。

### 合成用户调研数据分析（`data_source=synthetic`）

适用于 `ur-user-simulator` 生成的模拟问卷。读取 [references/io-contract.md](references/io-contract.md) 的合成输入契约：

- 必需：用户指定的 `survey_response_data/survey_responses_<run_id>.xlsx`，直接读取全量样本行及题目答案、状态、实际模型、条件性的回答原因和错误摘要。
- 必需：同课题已确认的 `questionnaire.md` 与 `survey-design-desc.html`，分别用于题目/逻辑和背景/目标/逐题用途。
- 可选：仅需披露样本构建方式时读取 `<WORK_DIR>/用户调研/personas_data/persons_summary.html`。不读取 `personas.json`、`persona_audit.json`、`persons/` 或逐人画像；汇总不能作为统计、分群、频次、引语或原因证据。
- 不引入问卷 `plan.json`、设计质量报告、回答批次质量报告或个人答卷目录；完成率、失败数等直接从 Excel 计算。

默认课题目录为 `<WORK_DIR>/用户调研/<YYYYMMDD><课题>/`；用户已指定其他目录时沿用该目录，不移动或改名输入文件。

### 真实用户调研数据分析（`data_source=real`）

- 必需：用户指定的真实问卷 Excel（`.xlsx` 或 `.xls`），可位于任意目录，不要求模拟器命名、目录、画像或专属字段。
- 可选：正式问卷、字段/选项编码字典、跳题规则、调研背景与目标、目标用户、采集时间、招募/抽样方式及权重说明。
- 默认一行一份回答；多选拆列、矩阵拆列或长表先明确映射。多张候选表、重复表头或回答与汇总混排时先辨认，必要时询问。仅有汇总数据时只做聚合描述，禁用受访者筛选、原始答卷交叉和定性证据回溯。
- 未提供字典时只分析可确认的题目与标签；不猜测编码、题型、量表方向或跳题条件。没有正式研究目标时标注缺口，输出探索性描述，不补造研究设计。
- 不要求用户 ID、完成状态、实际模型、回答原因或错误摘要。缺少状态及计算依据时，完成/失败/完成率为“不可计算”；没有开放文本时不生成原话、回答原因或定性主题。

## 来源差异与执行边界

以下差异在统一流程中应用，不另起执行流程：

| 项目 | 合成数据 | 真实数据 |
|---|---|---|
| 输入适配 | 按固定问卷及模拟器 Excel 契约解析 | 按实际工作表、列名和字典映射 |
| 批次与概览 | 从文件名取得 `run_id`；统计完成/失败、完成率、模型和错误摘要 | 保留原批次 ID；没有时生成分析运行 ID，并注明不是采集批次；只展示有依据的采集及质量指标 |
| 质量门槛 | 完成率低于 70% 时只输出质量诊断，不生成正式结论 | 按有效数据、缺失和采集偏差判断，不套用 70% 门槛 |
| 结论与引语 | 最高 `low`，限工具测试和假设生成；称“模拟回答/模拟原话”，禁止真实总体、显著性或市场推断 | 置信度依据覆盖、证据、反例与偏差，不因真实来源自动提高；脱敏后可引用真实原文，真实来源不等于代表性 |
| 页面与导出披露 | “合成模拟数据”，明确不能替代真实研究 | “真实用户调研数据”，披露采集和样本限制，不展示模拟器指标 |

**当前实现边界**：`scripts/generate_report.py` 的 CLI、校验和页面披露仍面向合成数据，交互及 Office 模板中也有合成专属提示。合成模式使用 [references/io-contract.md](references/io-contract.md) 的准备/渲染命令；真实模式在任务输出目录建立必要的解析和渲染适配，复用可独立使用的统计与交互逻辑，并逐项替换来源文案和专属指标。不能把真实 Excel 直接送入合成 CLI，也不能仅修改 `data_source` 后沿用合成页面。统一流程不代表 CLI 已支持任意真实 Excel。

## 统一执行流程

### 1. 数据清理和准备

检查已锁定输入的表头、样例行、全量数据与规则来源；建立列—题目映射、选项解码、多选拆分、量表方向和缺失标记。记录输入路径、工作表、原始行数、来源及运行 ID，用响应 ID 关联原文件/工作表/行号；真实数据使用匿名 ID。

原始 Excel 不改写。剔除非答卷行、证据明确的重复提交、非法选项/数值、重复排序、选择超限及违反已确认跳题/显示/结束规则的无效回答；每条剔除保留响应 ID、原始行和具体理由。相同答案不等于重复，不得因回答不支持预期结论而删除。

对语义矛盾、时长异常、直线作答、对象不匹配或错误摘要先复核，按明确规则处理；没有跳题规则时不将空白或表面矛盾直接判无效。区分缺失、跳题/未适用、拒答与有效的“无/不使用/0”，不默认插补或应用权重。提供权重时核验其含义，分开报告原始人数与加权估计，交互和导出口径一致。

将清理规则、剔除和待复核记录写入分析底稿；应用上表质量门槛。没有足够有效数据时仅交付诊断。合成批次题号重复、无法识别题型或 Excel 题列与正式问卷错配时停止，不静默丢列；失败行保留于总样本和完成率，不进入题目分析。

### 2. 描述性统计分析

从清理后的 Excel 答卷逐题计算，分母为实际有效回答数，不用总样本代替。具体方法见 [references/analysis-methods.md](references/analysis-methods.md)：

- 单选：各项频数、百分比和实际分母。
- 多选：按独立受访者去重的选择人数与受访者百分比，注明合计可超过 100%。
- 量表/NPS：确认编码、方向及数值含义后统计频数、均值、样本标准差、中位数和范围；不足 2 个有效值不计算标准差，不将任意分类编码当连续得分。
- 排序：第一选择、选择人数与平均名次；矩阵题保留子题和共同量表。保留已知零频选项；字典不完整时注明仅包含观察到的选项。

底稿保存 `sample`、`data_cleaning`、`descriptive_results`、目标映射与已有文本证据；不覆盖机械统计，也不先制造另一套未定义的 raw/structured 数据文件。缺失或不可计算的指标不写成零。

### 3. 高级与交叉分析

按 [references/analysis-methods.md](references/analysis-methods.md) 补全 `cross_tabulations` 和 `scale_quality`，不适用时记录原因：

- 分群只来自答卷中的明确字段；交叉表显示组人数、目标题有效分母、缺失数、人数与组内百分比，保留空组、零频选项及多选群体重叠和小样本限制。
- 信度仅用于同一构念、计分方向已统一且至少 3 个同量表题项，记录反向计分和缺失处理。不拼接不同构念，不把 Cronbach’s α 当效度证明；结构效度检验须满足题目设计、样本和方法条件，不虚构因子、拟合指标或效度等级。
- 默认描述差异。合成数据不作推断；真实数据也不默认作显著性或总体推断，用户明确需要时先确认抽样和方法条件，再报告效应量、不确定性及多重比较限制。

### 4. 定量与定性综合，形成关键结论

从已提供的调研背景与目的出发，先分析用户实际现状，再分析诉求与痛点，最后回答研究目标。将现状行为、概念意愿和研究者解释区分开；背景、目标或原因缺失时明确标记，不由统计分布补造。

按 [rules/evidence_rule.md](rules/evidence_rule.md) 补全底稿：

- `goal_coverage`：目标—题目—指标—证据映射及答案优先的 finding，未覆盖则标记 `evidence_gap`。
- `themes`：仅编码已有开放回答和回答原因，先拆原子观察再聚类；频次按独立受访者去重，记录证据 ID、`n/N`、反例、替代解释和置信度。无文本时明确无法开展定性分析，不从封闭选项推演原话。
- `segment_observations`：基于回答字段，标记 `source=response`，不得借用画像构建分群。
- `recommendations` 与 `limitations`：按“证据 → 解释 → 产品含义 → 下一步验证”写，交代证据强度、影响、成本/风险、可逆性、偏差和未回答问题；按来源差异控制结论强度。

形成几条目标对应的关键结论，保留相互矛盾的证据，不强行统一。组织2–3页结论 PPT（默认3页）：背景/目的与用户现状、用户诉求与痛点、调研目标与关键结论。每页配相关题目图表、实际分母、来源和必要限制；用户指定 PPT 工具时沿用其流程，不将内置导出冒称为该工具生成。

### 5. 渲染、验证和交付

两种模式复用 [templates/report_outline.md](templates/report_outline.md) 的布局和交互规范。生成 UTF-8 离线单文件 HTML，内嵌 CSS、SVG、脚本及交互必需的匿名封闭题答案，不依赖外部资源、不上传数据：

- **普通分析**：逐题独立切换表格、饼图、圆环、柱状、条形、折线；题目/选项筛选为同题 OR、跨题 AND，实时重算封闭题统计。
- **交叉分析**：与普通分析共用筛选，X 最多 2 题、Y 最多 10 题，支持添加/移除、交换与计算，显示有效分母和重叠限制。
- **调研分析结论**：只展示上述分析叙事和结论 PPT，不再追加“研究目标”“主题、痛点与需求”“建议与下一步验证”三个重复正文区块。
- **问卷质量报告**：集中分群与研究者分析、全批次描述统计、数据质量与清理记录、限制与未回答问题。与结论页均隐藏筛选、保持清理后全批次口径。
- 图形以百分比绘制并可见标注；多选饼图/圆环按选择人次归一化，其余采用有效受访者比例，折线不暗示时间趋势。下载支持真正 DOCX/PPTX/XLSX、结论 PPT 和交叉表 CSV，按当前 Tab 隔离导出。不提供保存报告、PNG/SVG 导出、执行摘要或证据索引。

身份字段、开放回答、回答原因及身份映射不进入 HTML 内嵌数据；真实引用先脱敏。分享前检查稀有组合、小组及文本的重识别风险，无法消除时交付聚合报告并明确禁用的交互，不静默暴露明细。

按 [rules/report_quality_rule.md](rules/report_quality_rule.md) 核对行数—剔除数—可分析数及逐题分母，抽查至少 3 项统计与 3 个已有证据回溯；不足时检查全部并注明，不能补造证据。检查四个 Tab、筛选、交叉、离线、来源、隐私、导出文件可重新打开及桌面/窄屏视觉。问题先修复再交付；未完成或受限的检查直接写入 HTML 的“问卷质量报告”Tab，标为待检查或说明限制，不将单元测试当视觉验收。

## 输出与交付约定

把技能目录记为 `<SKILL_DIR>`，调用目录记为 `<WORK_DIR>`。沿用用户指定输出位置；未指定时输出至 `<WORK_DIR>/用户调研/<YYYYMMDD><课题>/report_<run_id>/`，不同运行不覆盖。所有产物在任务目录，不写入 Skill：

HTML 文件名使用 `<YYYYMMDD><调研课题>_调研报告.html`。日期默认取报告生成日期；用户明确指定日期时沿用（合成 CLI 使用 `--report-date YYYYMMDD`）。课题优先取正式课题名，不重复日期、问卷或报告后缀；清理文件名非法字符，不能含目录跳转。例：`20260918手机相册高阶AI特效付费意愿调研_调研报告.html`。

- `analysis_summary.json`：可复核分析底稿，默认命名沿用现有脚本；用户指定名称时使用实际文件路径。
- `<YYYYMMDD><调研课题>_调研报告.html`：交互报告；“问卷质量报告”Tab 内完整展示输入、清理、统计/证据抽查、来源、隐私、交互/导出及视觉检查记录，不再单独生成 `report_quality.md`。

- 结论 PPT：2–3页、含调研数据图表的 PPTX，随报告提供下载；未完成时明确说明，不宣称已生成。

回复先给报告路径、输入 Excel/工作表和运行 ID，再简述关键发现与主要限制。合成数据明确不能替代真实研究；真实数据说明结论适用的人群和范围。
