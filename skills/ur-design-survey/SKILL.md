# 用户调研问卷设计

先明确问卷要支持的产品决策，再把调研问题拆成可收集的证据、题目和答题路径。

## 输入契约

设计新问卷至少需要：调研主题、产品背景、产品决策、研究目标和目标用户。产品阶段、概念/方案、题量要求、已有材料及渠道、时间、语言、隐私等约束按实际情况提供。

- 产品决策不能只写“了解需求”，应改写为需要作出的具体选择并请用户确认。
- 研究目标控制在 1–3 个；目标用户用角色、场景或近期行为定义。
- 只有缺失信息会改变调研问题、目标用户或概念材料时才提问，一次最多确认 3 项；其他缺口标为假设后继续。
- 优化现有问卷时必须取得原问卷，并保留用户指定的目标、题量上限和必留题。
- 多个用户研究 Skill 共用课题或受众时，按 [共享上下文规格](references/shared-context-schema.md) 读取或更新 `shared_context.md`。

## 工作流程

### 1. 定义调研问题并形成输入摘要

先区分四层信息：

1. **业务背景**：发生了什么，为什么现在需要研究。
2. **产品决策**：研究结束后要决定做什么、不做什么或先做什么。
3. **调研问题**：必须从用户处获得哪些未知信息，才能支持该决策。
4. **研究目标**：本次问卷能够回答的 1–3 个目标，不承诺问卷无法证明的因果结论。

产品决策应可执行，例如：“决定是否进入分相册控制原型验证，以及首版优先覆盖哪些控制能力。”据此将宽泛目标改写为具体调研问题，例如：“目标用户近期如何控制照片同步范围”“现有做法造成哪些实际问题”“哪些条件会影响其尝试新方案”。

形成研究输入摘要，至少包含：主题、背景、产品决策、调研问题、研究目标、目标用户、产品阶段、题量要求、概念材料、约束和必要假设。需要跨 Skill 协同时，再写入并校验 `shared_context.md`。

### 2. 建立目标—证据清单

每个研究目标都要明确“需要判断什么”“用什么证据判断”“证据如何影响决策”：

| 目标 | 需要判断 | 优先证据 | 决策用途 |
|---|---|---|---|
| G1 行为基础 | 目标行为是否真实存在 | 近期是否发生、频率、最近一次任务与做法 | 判断问题是否存在于目标人群 |
| G2 问题价值 | 问题是否值得解决 | 实际发生的问题、影响、后果、当前应对 | 判断机会强度和优先问题 |
| G3 方案价值 | 概念或方案是否值得继续 | 任务匹配、增量价值、顾虑、采用条件与取舍 | 判断是否继续及优先范围 |

具体课题可以增删目标，但不能直接照抄示例。删除无分析用途、重复测量、用户难以回忆或不会改变决策的证据。每项核心证据至少对应一道题；一道题能可靠覆盖多个目标时不重复提问。

### 3. 选择问卷类型、模块并确认研究思路

以主要产品决策选择一份结构示例：

| 研究情境 | 结构示例 | 核心证据链 |
|---|---|---|
| 尚无明确方案，识别机会与真实问题 | [原始需求洞察](templates/questionnaire-original-needs-discovery.md) | 近期行为 → 问题 → 后果 → 当前应对 |
| 已有一个功能假设，判断是否继续验证 | [关键假设验证](templates/questionnaire-key-hypothesis-validation.md) | 目标行为 → 问题基础 → 概念价值 → 采用条件 |
| 已有多个可比方案，需要确定取舍 | [方案选择](templates/questionnaire-solution-selection.md) | 中性呈现 → 首选 → 排斥理由 → 顾虑 |
| 产品已经上线，需要评价现有体验 | [满意度调查](templates/questionnaire-satisfaction-survey.md) | 近期使用 → 整体评价 → 维度诊断 → 低分原因 → 改进优先级 |

示例只提供证据结构、题序和逻辑模式；必须替换业务语境、时间窗、选项和筛选条件。目标横跨多类时，以主决策对应的示例为骨架，不要直接拼接多份问卷。

再按 [问卷模块设计](references/survey-patterns.md) 选择必要模块。题序通常为：`人口特征 → 用户筛选 → 近期行为 → 问题与当前应对 → 概念/方案 → 意愿与取舍 → 开放补充`。没有分析用途的人口特征和没有待验证方案的概念模块应删除。

进入逐题设计前，必须展示“用户研究设计确认卡”（格式见输出契约）并取得确认；用户已明确确认同等信息或明确要求直接出稿时无需重复确认。

### 4. 规划题量并逐题设计

#### 题目数量

- 用户给出固定题数或上限时严格遵守；没有要求时默认设计 10–12 题。
- 题数包含所有编号题和条件显示题，不包含开场语、概念卡和结束语；同时说明最长路径的实际作答题数。
- 先为目标—证据清单中的核心证据分配题目，再加入必要的筛选和分析变量；不能为凑满默认题数增加题目。
- 超出题量时依次删除无决策用途的人口特征、重复态度题和低价值开放题，不删除核心筛选或关键证据题。

#### 题型数量分布

10–12 题问卷可从以下基准开始，并按问卷类型调整；各题型数量之和必须等于总题数：

| 题型 | 基准数量 | 调整原则 |
|---|---:|---|
| 单选题 | 4–6 | 用于筛选、频率、主任务、首选方案和总体评价 |
| 多选题 | 2–3 | 用于已发生行为、问题、原因或条件；限制最大选择数 |
| 量表或矩阵题 | 0–2 | 满意度和强度测量使用；原始需求洞察通常少用或不用 |
| 排序或 Top-N | 0–1 | 只有需要明确优先级或方案取舍时使用 |
| 填空题 | 1 | 通常放在末尾并设为选填 |

该分布不是配额。满意度调查可使用 2 道量表题；方案选择应优先保证直接取舍；没有概念或优先级目标时，把相应题量分配给行为和问题证据。

#### 核心设计规则

- 题干格式统一为 `Q1【单选题】（必填）题干` 或 `Q1【单选题】（选填）题干`。
- 行为题使用明确时间窗或“最近一次”；一题只测一个概念，不使用诱导、双重问题、内部术语或隐藏前提。
- 单选选项互斥且基本穷尽；多选限制最大选择数，排他项不能与其他项并选。
- 量表方向一致、端点明确；中间项必须可解释，并为无法判断者提供出口。
- 概念卡保持中立，只描述任务、方式、输出、限制和未知项；行为与问题题必须在概念卡之前。
- 意愿题绑定具体任务、时间和必要条件，不把陈述意愿解释为实际采用率。
- 优先级使用排序、Top-N 或直接方案取舍，不让所有能力都被评为重要。
- 年龄、性别、收入、城市等信息只有在筛选、配额或分析确有用途时才收集。

题型选择、选项、量表、措辞，以及 `题目关联`、`跳题逻辑`、`选项关联`、`填写提示` 的完整规则统一见 [题目设计标准](references/question-design-standards.md)，主文件不重复定义。

### 5. 验证答题路径

至少模拟三类用户：符合条件且有近期经历、无近期经历或不确定、命中边界答案或无法评价。确认每条路径可到达正确结束页，隐藏题不会被强制填写，退出用户不会回答体验题，引用题始终有可用选项。

### 6. 生成交付文件并质量审查

先完成统一题目清单，再生成三份交付文件。以 `questionnaire.md` 为题干、选项和逻辑的唯一来源；其他文件只通过题号引用，不复制完整问卷。

运行：

```bash
python skills/ur-design-survey/scripts/lint_questionnaire.py <questionnaire.md>
```

再按 [问卷发布检查清单](references/questionnaire-logic-checklist.md) 审查目标覆盖、路径、平台可实现性、答题成本和隐私。阻断问题修复后再交付。

## 输出契约

### 用户研究设计确认卡

逐题设计前向用户展示：

```markdown
## 用户研究设计确认卡

- 调研主题：
- 产品决策：
- 调研问题：RQ1…；RQ2…
- 研究目标：G1…；G2…
- 目标用户与筛选条件：
- 产品阶段与问卷类型：
- 目标—证据摘要：
- 计划模块与题序：
- 题目规划：总题数…；最长路径…；单选…/多选…/量表或矩阵…/排序或 Top-N…/填空…
- 概念或方案材料：无 / 已提供 / 待补充
- 关键假设与约束：

请确认：确认 / 修改 / 重新设计
```

用户选择“修改”时只更新受影响字段并重新展示；选择“重新设计”时回到 Step 1。确认卡不单独保存为最终交付文件，其确认内容写入 `design-doc.md`。

### 最终文件

默认保存到：

```text
output/<YYYYMMDD><课题>/<课题>_Questionnaire/
```

| 文件 | 是否必需 | 内容 | 模板 |
|---|---:|---|---|
| `design-doc.md` | 是 | 背景、产品决策、调研问题、研究目标、模块、目标—证据—题号映射和分析建议；不复制完整题干或选项 | [设计说明](templates/design-doc.md) |
| `questionnaire.md` | 是 | 可直接配置的受访者文案、概念卡、全部编号题，以及按需出现的关联、跳转、引用和填写提示 | 按 Step 3 选择结构示例 |
| `quality-report.md` | 是 | 结构检查、路径模拟、人工审查、问题处置、修改记录和剩余限制 | [质量报告](templates/quality-report.md) |

当前不生成 JSON 问卷文件。`questionnaire.md` 是唯一问卷正文来源；`design-doc.md` 保存研究设计和分析用途；`quality-report.md` 保存质量证据与发布限制。

## 优化现有问卷

不擅自改变原研究目标。依次修复筛选与跳转、诱导和双重问题、选项与量表缺陷，再删除无决策用途的题并调整题序。输出完整修订稿；在 `quality-report.md` 中按题号记录原问题、修改、理由和历史数据可比性影响。

## 交付给用户

展示文件路径、总题数与最长路径题数、预计时长、问卷类型、题型分布、质量结果和剩余限制，并请用户选择“确认 / 修改 / 重新设计”。用户确认前不启动模拟作答或报告分析。
