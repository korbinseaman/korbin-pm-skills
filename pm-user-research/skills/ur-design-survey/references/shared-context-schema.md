# 任务级共享上下文

## 用途与位置

当一项由用户提供或确认的信息会被两个及以上 Skill 使用时，写入普通 Markdown 文件：

```text
<WORK_DIR>/用户调研/<YYYYMMDD><课题>/shared_context.md
```

该文件是跨 Skill 读取用户确认信息的唯一入口。下游 Skill 读取同一路径，不依赖上一个 Skill 的对话或私有工作文件。

## Markdown 模板

```markdown
# 用户研究共享上下文

## 任务信息

- 任务标识：20260815图库AI修图用户需求调研
- 调研主题：图库AI修图用户需求调研

## 目标用户

### 全量候选群体

- 学生群体
- 上班族
- 宝爸宝妈
- 内容创作者

### 已选目标群体

- 学生群体
- 上班族
- 宝爸宝妈
- 内容创作者

### 纳入条件

- 18岁及以上智能手机用户

### 排除条件

- 无

## 确认信息

- 排除条件由用户明确确认：否
- 状态：已确认
- 确认人：用户
```

## 写入规则

- 使用上述固定标题组织内容，但正文保持普通 Markdown，不嵌入 JSON、YAML 或 frontmatter。
- 只写用户提供或明确确认、且至少有两个 Skill 会使用的信息。
- “全量候选群体”保存全部候选产品受众；“已选目标群体”保存用户实际选择。
- “排除条件”默认为“无”。只有用户主动提出并确认具体排除对象时，才写入具体条件，并将“排除条件由用户明确确认”写为“是”。
- 问卷题目、研究工具、产品决策、研究目标、假设、概念评价和分析结论不得写入此文件。
- 用户修改共享信息时原地更新此文件，再由消费者重新读取；不得分别修改多个 Skill 的私有副本。

## 读取规则

- `ur-design-survey` 在后续设计中从本文件读取已确认的课题和受众。
- `ur-generate-personas` 只接受本文件作为用户画像输入，并只读取任务信息、目标用户和确认信息。
- 其他 Skill 需要这些信息时读取同一路径。
