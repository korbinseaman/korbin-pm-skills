# AI 产品经理工作流演变：真实案例深化版规划

## 分享定位

- 受众：产品经理团队；默认了解大模型与常见 AI 工具，但未必系统开发过 Skill。
- 时长：45 分钟，其中讲述约 39 分钟，讨论与问答约 6 分钟。
- 核心观点：AI 对产品经理的价值不在于更快地产出文档，而在于把证据、决策、执行和验证做成一套可复用、可追踪、可停损的工作系统。
- 两个真实工作材料：
  1. `手机图库 AI 功能使用与需求调研`：用 12 题问卷说明研究目标如何转成决策证据、题目逻辑和结构门禁。
  2. `鸿蒙图库——一句话清理图片产品方案决策汇报`：说明自然语言能力如何被收敛成低歧义 MVP、风险护栏、PRD 验收和阶段门。
- 表达原则：不把合成数据当真实市场结论；不把产品假设包装成已验证事实；所有“若……则……”结论明确标为预注册分析规则或待验证假设。

## 两个案例必须讲透的产品经理价值

### 案例一：图库 AI 需求问卷

1. **避免把功能喜好当真实需求**：先问过去 3 个月使用频率和最近一次任务，再问未来诉求。
2. **把“想要很多”压缩成一个取舍**：Q9 收集需求广度，Q10 强制选择一个，Q11 追问原因，Q12 落到具体发生场景。
3. **把体验问题转成方案约束**：若 Q7 出现“担心误删/无法撤销”，且 Q8 表现为信任下降或放弃使用，则方案必须加入预览、确认和恢复，而不是只优化识别准确率。
4. **让研究交付可复用**：同一份 Markdown 作为事实源，自动派生评审版和平台配置版，减少三份文档漂移。
5. **在发放前暴露问题**：结构 Lint 检查互斥、分支、题量、题目关联；合成调研只用于试跑逻辑和管线，不用于估计真实比例。

### 案例二：一句话清理图片

1. **把卖点改写为责任边界**：“一句话删除”看似高效，但把自然语言歧义放大成误删；最终决策是系统负责生成可解释候选，用户保留最终删除责任。
2. **用风险分层代替功能堆叠**：低歧义任务进入确认执行；质量语义增加解释；人物、票据、私密等高风险对象只筛选不自动执行。
3. **把 PRD 做成可追踪账本**：每条需求都能回到证据或假设，并映射状态、异常、验收和埋点；无法映射索引能力的条件不生成删除计划。
4. **让原型承担风险验证**：原型不是画正常流程，而是验证用户能否在执行前复述范围、能否排除误选、能否理解降级原因、能否找到恢复入口。
5. **用阶段门降低沉没成本**：本次只批准方案方向、原型测试和技术预研；误选不可控、解释不可理解、端侧性能不达标或隐私红线不通过时停止立项。

## Skill / Command 开发讲法

以两个 Skill 为例，讲同一条开发流水线：

```text
一次性提示词
→ 明确触发条件与不适用范围
→ 固化必填输入和确认卡
→ 拆分步骤、状态和停止条件
→ 将方法放入 references/，格式放入 templates/
→ 将可确定判断放入 scripts/
→ 用真实案例做 eval，记录失败并更新契约
→ 通过命令调用，交付稳定文件而不是一段聊天内容
```

- `$ur-design-survey`：重点展示“决策—证据—题目”契约、三个输出文件和 Lint。
- `$pm-system-app-competitor-matrix`：重点展示 `ResearchUnit`、`EvidenceRecord`、检索停止规则和未知/冲突状态。
- Command 示例：

```text
$ur-design-survey 调研课题：手机图库 AI 功能需求；目标：识别高频任务、主要问题与优先功能；场景：原始需求洞察；问卷不超过 12 题。
```

```text
$pm-system-app-competitor-matrix 分析图库 AI 清理；重点关注候选解释、确认、撤销、隐私和降级机制；所有结论保留证据等级。
```

## 其他 Skill 的组合方式

不要逐个念功能清单，而是按产品生命周期说明组合关系：

```text
机会识别：新品速递 / 竞品追踪
→ 问题定义：用户研究 / 竞品矩阵
→ 决策设计：产品方案 / PRD / 原型
→ 上线表达：功能命名 / 微文案 / 版本说明
→ 持续学习：用户反馈 / 竞品变化 / 指标复盘
```

团队推广时优先建设高频、跨人协作、返工昂贵、质量可检查的任务；低频且高度依赖个人判断的任务先保留为模板或检查清单，不急于 Skill 化。
