# Three-Part Content Framework

## Part 1 — 手机新品概览

Cover every announced phone model in scope. Prefer a native editable matrix for:

- Model, positioning as described by sources, launch market/date.
- Price by available storage/configuration tier; label currency, region, tax basis when relevant, and launch versus promotional price. If only a starting price is known, say “起” and do not invent the remaining tiers.
- Chip and documented CPU/GPU/NPU changes; attribute manufacturer benchmarks and retain comparator and measurement conditions.
- Display size, refresh rate, resolution/brightness where material; body materials, dimensions and weight.
- Rear and front camera lenses: role, pixels, focal length/aperture, sensor or stabilization changes where reported. Distinguish optical zoom, crop-based optical-quality zoom and digital zoom.
- Battery, charging, connectivity hardware, durability and other major documented upgrades.

State “升级” only against an identified predecessor/configuration supported by sources for both sides. Do not infer speed, image quality, battery life or AI capability solely from specifications. Put capture interactions in Part 3; summarize lens hardware here.

## Part 2 — 操作系统与系统软件升级

Explain the OS version shipped with the new devices, system-wide upgrade themes explicitly described by sources, supported devices and rollout schedule. Include system visual/interaction changes, performance/power, security/privacy, system AI platform and cross-device capabilities where evidence exists.

Use a short matrix: **升级项 / 官方或媒体描述的变化与卖点 / 适用范围与上线状态 / 来源**. Attribute claimed improvements and distinguish media testing from manufacturer claims. Mark “此前已公布、本场搭载” when appropriate.

Keep this part at system level. Mention a key application capability briefly and point to Part 3 for its detailed experience; avoid repeating the same prose.

## Part 3 — 重点应用与功能特性

Use these categories as a coverage checklist, not a mandate to invent content:

| Category | Coverage |
| --- | --- |
| 系统应用AI | assistant, search, screen understanding, generation, editing, automation and actions inside system apps; preserve service/model dependencies |
| 相机 | capture entry, framing, computational imaging, photo/video modes, recording and professional workflow |
| 图库 | browsing, organization, search, memories, editing, cleanup, sharing, sync and storage behavior |
| 桌面与锁屏 | home screen, launcher, widgets, icons, notifications, control center, lock screen and personalization |
| 通信 | calls, messages, contacts, translation, spam filtering, satellite communication and related software behavior |
| 其他系统应用 | notes, calendar, browser, files, productivity, privacy and cross-device interactions when announced |

For each key feature extract **特性名称 → 来源描述的场景 → 入口/操作 → 展示或宣称的结果/卖点 → 适用条件 → 来源**. Use only supported steps. If a press release names a capability but gives no interaction, describe it at that level and mark the missing detail instead of reconstructing it from older versions.

Prioritize source-supported event highlights, substantial experience changes and well-documented demonstrations. Give Part 3 roughly half the content pages, adjusting to evidence. Combine minor related features in a matrix. If no change is found in a category, briefly state “已查阅资料未见新增披露” where useful, or omit a dedicated page; never assert that no change exists anywhere.

## Writing boundaries

Paraphrase faithfully and preserve qualifiers. Use “官方称” for advertised benefits and “据 ×× 实测，在……条件下” for measured outcomes. Attribute media opinions such as “更易用” instead of adopting them as fact. Claims of first, best, fastest or percentage improvement need their original scope, comparator and source.

Do not add original PM takeaways, HarmonyOS comparisons, proposed KPIs, development priorities, recommendations or speculative industry narratives. Source-based organization and concise synthesis are allowed; new causal claims or invented user benefits are not.
